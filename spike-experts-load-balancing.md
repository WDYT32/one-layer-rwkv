# Механізм Спайкових Експертів (Fatigue Load Balancing)

Цей документ описує виключно механізм load balancing (fatigue/рефрактерність), виділений з `recurrent-moe-architecture-formulas.md` та `recurrent-moe-architecture-v3.md`. Решта архітектури та метод навчання не зачеплені.

## 1. Fatigue-маскування перед softmax (Формалізація)

Кожен експерт `e` має лічильник fatigue (втоми) `F_e(t) ∈ ℝ`:

```
F_e(t) = γ · F_e(t−1) + κ · 𝟙[expert e called at t−1]
```

де `γ ∈ (0,1)` — швидкість релаксації, `κ > 0` — приріст за виклик.

**Жорстке маскування:**

```
logit_e(t) = { x W_R[:,e]     якщо F_e(t) ≤ θ
             { −∞             якщо F_e(t) > θ
```

Застосовується *до* семплювання чи argmax (маскує кандидатів, не замінює стохастичність вибору серед недоступних).

### Чому жорстке маскування, не м'який штраф

При дискретному top-k вибір — це частковий argmax, недиференційовний: градієнт не поширюється для необраних експертів. М'який штраф на логіт перед argmax все одно дає різкий перехід у виборі (експерт або перетинає поріг і випадає з top-k, або ні) — без збереження реальної диференційованості для невибраних альтернатив. Тобто м'якість не дає переваги в дискретному режимі, а лише додає гіперпараметр без компенсації. Жорстке маскування простіше й чесніше відображає природу рішення.

## 2. Концептуальне обґрунтування (заміна / доповнення load-balancing loss)

- **Біологічна паралель:** Пряма паралель до біологічної рефрактерності нейронів. Підтверджено прецедентом SpikeMoE (2026) — competition-refractory-inhibition routing, ablation показує: без рефрактерного періоду routing страждає від "expert collapse", де один експерт монополізує активацію.
- **Протиставлення глобальному балансу:** Стандартний auxiliary load-balancing loss тисне до рівномірності статистично-глобально, що може шкодити корисній спеціалізації (tension між балансом і спеціалізацією, задокументована в EMoE-роботі).
- **Збереження спеціалізації:** Fatigue не забороняє спеціалізацію (хто типово обробляє що), лише обмежує послідовну монопольну експлуатацію одного стану в часі.
- **Диверсифікація як цільовий механізм:** Диверсифікація через fatigue — не компроміс заради стабільності, а цільовий механізм. Top-k недиференційовний: градієнт не йде для необраних експертів, тому forced exploration через fatigue (через недоступність улюбленого експерта) — єдиний спосіб дати неврахованим альтернативам шанс отримати градієнт. Природна диверсифікація (композиція кількох різних спеціалізованих експертів в одному ланцюжку, напр. "трохи математики, трохи програмування") — бажаний результат, що стимулює кросдоменні взаємодії, узгоджені з curriculum-дизайном.

## 3. Референс-формалізація (SpikeMoE, 2026) — для неперервної динаміки

Якщо в майбутньому знадобиться замінити дискретний fatigue-лічильник на неперервну мембранну динаміку (ближче до spiking-натхнення):

**Мембранний потенціал:**
```
V[t] = V[t−1]·(1 − 1/τ) + I[t]
```

**Латеральне гальмування** (опціонально, для крос-експертної конкуренції):
```
V_inhibit[t] = V[t] − S[t−1]·(L ⊙ M)·γ
```
де `L ∈ ℝ^(E×E)` — навчувана матриця гальмування (нуль на діагоналі), `M` — маска гальмування, `⊙` — добуток Адамара.

**Рефрактерний лічильник** (прямий аналог нашого fatigue, але дискретна формула decay через лічильник, не експоненційне згасання):
```
S[t] = { 1   якщо V[t] ≥ V_th[t]  і  R[t] ≤ 0
       { 0   інакше

V[t] ← 0,  R[t] ← t_refractory   коли S[t] = 1
R[t+1] = max(0, R[t] − 1)
```

**Ablation-результат з SpikeMoE:** пряме емпіричне підтвердження необхідності механізму — без рефрактерного періоду відбувається колапс експертів.
